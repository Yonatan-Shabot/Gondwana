# Gondwana

Gondwana is a universal, modular Helm library chart designed to deploy any application with plug-and-play ease. 

Built specifically for developers who aren't Kubernetes or Helm Experts, Gondwana bridges application-level and infrastructure-level configurations into a single, highly readable `values.yaml` file. By abstracting away the complex boilerplate of Kubernetes manifests, it allows teams to focus on their apps while ensuring a robust, standardized deployment structure underneath. Using a modular approach, you can define different types of micro-services in your application, please see the values examples for more details.

## Getting Started

These instructions will guide you through including the Gondwana library chart in your project to handle your application deployments.

### Prerequisites

To use Gondwana, you will need the following installed and configured on your cluster:

* Helm v3+
* Kubernetes v1.25+ (or OpenShift 4.12+)

### Installing

Because Gondwana is built as a **Library Chart**, it is not deployed on its own. Instead, you include it as a dependency in your application's Helm chart.

1. Open your application's `Chart.yaml` file.
2. Add Gondwana to your `dependencies` block:

```yaml
apiVersion: v2
name: my-awesome-app
description: A Helm chart for Kubernetes
type: application
version: 0.1.0
appVersion: "1.0.0"

dependencies:
  - name: gondwana
    version: 0.1.0
    repository: # Wait a minute, this isn't even released yet!
```
3. Update your chart dependencies to download Gondwana:

```Bash
helm dependency update
```
4. You can now define your clean, unified configurations in your values.yaml and let Gondwana render the underlying Kubernetes resources.

### Running the tests
Automated testing suites for the Gondwana chart are currently in development and will be available in future releases.

### Deployment
When deploying your applications to a live production cluster using Gondwana, pay special attention to your Ingress configurations.

Ensure that:
A valid Ingress Controller (e.g., NGINX, Traefik, HAProxy) is deployed and actively running on your target production cluster to handle the ingress resources generated by Gondwana.
